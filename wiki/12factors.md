# Архитектура проекта «Alexandria» по методологии 12-Factor App

## 1. Codebase (Единая кодовая база)

- Репозитории:
  - `Backend` — C# ASP.NET
  - `Frontend` — TypeScript + React + Vite
  - `Docs` — Документация
- Ветки:
  - `main` — production
  - `develop` — staging
  - `feature/*` — фичи

---

## 2. Dependencies (Зависимости)

- Все зависимости явно объявлены:
  - Backend: `*.csproj`
  - Frontend: `package.json`

- Использование:
  - `dotnet restore`
  - `npm install`

---

## 3. Config (Конфигурация)

Backend:

- Часть конфигурации хранится в **переменных окружения**,
другая а `appsettings.*.json`.


Frontend:
- Используются переменные окружения через механизм Vite:
  - `.env`
  - `.env.development`
  - `.env.production`

- Секреты не хранятся в репозитории

---

## 4. Backing Services (Внешние сервисы)

Все внешние сервисы подключаются как ресурсы:

- PostgreSQL → база данных
- MinIO → хранение изображений

---

## 5. Build, Release, Run

Разделение стадий:

### Build
- Сборка (`docker build`)

### Release
- Формирование Docker-образа
- Подстановка конфигурации

### Run
- Запуск контейнера

CI/CD:
- push → build → test → deploy

---

## 6. Processes (Процессы)

Процессы не сохраняют состояние. Они проводят манипуляцию с БД посредством транзикций и возвращают ответ.

---

## 7. Port Binding (Привязка портов)

Backend сам предоставляет HTTP API через встроенный сервер Kestrel:

```
http://0.0.0.0:5000
```

* Приложение напрямую слушает порт `5000`
* Не используется внешний web-сервер или reverse proxy
* Доступ осуществляется напрямую к контейнеру/сервису Backend
* Конфигурация порта задаётся через переменные окружения

---

## 8. Concurrency (Масштабирование)

Можно масштабировать при помощи запуска нескольких служб backend
PostgreSQL остается единым источником

## 9. Disposability (Быстрый старт и остановка)

Так как backend запускается в докере, то его запуск и остановка реализуется встроенными командами докер. У нас нет очередей и нет фоновых задач.

---

## 10. Dev/Prod Parity (Сходство окружений)

* В Dev все сервисы поднимаются локально через `docker-compose`

* В Prod используются managed-сервисы и облачные платформы:

  * Backend/Worker — Render / Railway
  * База данных — managed PostgreSQL
  * Хранилище — S3-compatible

* Различия только в:

  * способе деплоя
  * endpoint’ах сервисов
  * переменных окружения

* Контракты взаимодействия (API, схемы данных) полностью совпадают


---

## 11. Logs (Логирование)

Логи пишутся в stdout/stderr

---

## 12. Admin Processes (Админ-процессы)

Одноразовые задачи выполняются отдельно:

* Миграции БД:

  ```
  dotnet ef database update
  ```
